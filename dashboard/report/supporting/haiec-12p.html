ASSURE · EVIDENCE FIRST

Evidence before conclusions

HAIEC does not take the system's word for what happened. Submitted evidence is normalized, digest-bound and evaluated deterministically — the same input always produces the same result.

The assurance flow

Synthetic source worldMES transactions, torque-tool events, release readbacks, scheduling and supplier records — recorded, not narrated.
Normalized evidenceTyped records bound to case identity; unmarked input stays digest-and-refs only.
Deterministic evaluationManufacturing detector, delegated-action comparison, scoped effect witness, authority planes — replayable, verbatim.
Persisted exporthaiec-evaluation-export-1.0.0 — digest-verified in the browser before any finding is displayed.
Public receiptView-only verification on haiec.com — anyone can confirm integrity without an account.
Integrity property: the same evidence always yields the same evaluation. A digest mismatch withholds the report — it never softens it.

Scenario records carry declared vs observed timestamps; freshness is derived from the fixed 2026-10-15 reference clock.

GOVERN & OPERATE · HUMAN REVIEW

The accountable review lifecycle

Request → boundary check → accountable role → notification previews → decision → scoped operating status → monitoring follow-up.

Requester

System proposes a consequential change — e.g., Station 217 requests autonomous MES write expansion (DEMO-REQ-SYS-217-06).

Boundary check: outside approved scope → human review required.

Reviewer — fictional Quality Director

Assigned accountable role; requesting and approving roles stay separate.

Email and text previews are shown in the demo — no real dispatch is connected.

What a pending decision means

While DEMO-REQ-SYS-217-06 is pending, the consequential expansion does not proceed — a subsequent write attempt (DEMO-GW-SYS-217-02) is held at the demonstration gateway. Lower-risk advisory work continues inside the approved scope. Pending is an operating state, not a failure.

Two contrasting outcomes

SYS-340 Vision Inspection — approved within scope; advisory quality reviews proceed under conditions and expiry. SYS-SCH5 Scheduling — production-floor control writes rejected; scope boundary held.

All reviewer activity in this document is authored scenario material — the real HAIEC governance APIs are authenticated and tenant-bound; nothing here calls them.

STATION 217 · TWO LINKED EVENTS

Detection first. Demonstrated control second.

EPISODE A · OCT 14 · RECORDED EVIDENCE

What HAIEC detected

Delegated target WO-217-4802 → committed effect on WO-217-4803. The saved evaluation detected the target divergence: MFG-EFF-001 MATCH · DAI BROADER · result REVIEW.

Verified export SYS-217-WRONG_TARGET — digest-bound, publicly checkable. Detected ≠ prevented.

EPISODE B · OCT 15 · GOVERNANCE SCENARIO

What the operating model shows next

Request DEMO-REQ-SYS-217-06 expands autonomous MES write authority → outside approved scope → Quality Director review → notification previews → decision pending → subsequent attempt DEMO-GW-SYS-217-02 held at the demonstration gateway → advisory work continues.

Simulated hold — legitimate blocked-action demonstration; no dispatcher, email or SMS is connected.

Why the distinction matters

The recorded mismatch is a finding established by deterministic evaluation — it already happened. The held write is a subsequent, simulated request demonstrating how consequential change waits for a human. Merging them would misstate both: detection is proven; prevention of the earlier event is not claimed.
