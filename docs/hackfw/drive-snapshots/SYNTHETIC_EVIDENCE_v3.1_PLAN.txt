1. North star and non-negotiable source truth
Build a synthetic evidence collection that looks and behaves like the real external sources an enterprise would connect, while remaining reproducible, independent of expected results, safe and openly synthetic. Do not add synthetic data solely to inflate volume. Every new record must enable an executable capability or an explicit evidence gap: identity, authorization, effective grants, code capability, request/decision/dispatch, observed transaction, independent effect witness, continuity, drift, control proof or provenance integrity.
Existing preserved state: nine manufacturing systems, 16 agent roles, 216 v3 sensor samples, 36 v3 scenario runs, 336 manifest-pinned artifacts, old v2 SYS-217 records and 27 v1 persisted evaluations. v3 traces, IAM, policy and native records are candidate data, not already-qualified HAIEC evidence. Never overwrite v3, v2, or v1 evaluation IDs.

3. Source family inventory — what to enrich
A. Requested/agent: user task, prompt-intent sample, role/instance ID, A2A parent delegation, function/MCP call args and typed resource target; hidden chain-of-thought not required or requested. Expected: discover agent actions, proposed consequence, first-seen tool and broadened scope.
B. Authority: versioned approved operating-envelope proposal, explicit human approval with SoD, quantity/target/expiry, denies, revoke/pause, direct-write bypass, single-use approval and correction version. Expected: permission != delegation; exact authorized effect envelope.
C. IAM/code: AWS-style candidate role plus real provider-specific source shape for access simulation with SCP/boundary/session policy where applicable; OpenAPI/MCP manifest and an actually reachable injected code path; tool definition != proven code capability, declared grant != effective grant.
D. Runtime: OTLP traces with exact spans/trace IDs, first-seen tool, call frequency, retries, token usage and cost, model/version/context, independent collector heartbeat and missing window. Behavioral novelty is signal, not authorization violation.
E. Native effects: MES work-order transaction and independent QMS readback; ERP PO+vendor; APS plan version; CMMS work request vs repair; WMS pick/ship/quality hold; dyno emulator setpoint; no HTTP success as native effect. Include native state version, before/after, units, source time and idempotency ID.
F. Visual/perception: synthetic or properly licensed station frame / part defect references, 24 baseline labeled images may stay but expand representative holdout with independently authored ground truth, model version, lighting, camera, part revision and false-positive/false-negative cases. Do not invent measured accuracy. Actual image assets are optional unless the demo claims computer-vision detection.
G. Supply-chain/industrial: QMS PPAP supplier-part-site-revision-expires, serial/lot provenance, engineering BOM/recipe revision, line station or job order, repair/return-to-service evidence, audit trail tampering, low-fidelity source/deferred industrial format demonstrations.

5. Four scenario modes and the fifth comparison dimension
EXPECTED_BASELINE: normal simulated proposal, attributed approval, action and target witness — with only actually qualified evidence accepted by HAIEC. EVIDENCE_DEGRADED: intentional missing target readback + collector/heartbeat failure; UNKNOWN effect. WRONG_TARGET: approved vs actual target divergence with a native simulator witness; no client-supplied violation verdict. REMEDIATED: new separate source run and policy version shows denied wrong-target request, no-effect readback and corrected authorized action + witness. All four are independently versioned and digest-pinned.
FIFTH DIMENSION: evidence SUBSET vs ENRICHED is not a fifth scenario type. Re-evaluate the SAME raw run identity under two immutably saved evidence snapshots, with explicit included/excluded sourceRefs, to demonstrate how source coverage improves without claiming remediation. Prioritize SYS-217 first; make other eight reproducible under same pattern.
