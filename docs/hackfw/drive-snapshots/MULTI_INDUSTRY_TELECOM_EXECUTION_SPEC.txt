1.1 Telecom case storyline for the derivative dynamic HTML
Telco hero: 'Which AI-directed network change was requested, who authorized it, what RAN/Core/OSS route was reachable, and what target slice and service state were observed?' Use exact scenario identity and explicit recorded stage order; do not infer change chronology from timestamps alone. Show AL0 reference baseline, AL1 evidence degradation and AL2 proposed compromised target binding only to the extent source fixtures support those labels. A missing KPI/observation means effect UNKNOWN; an agent/audit hash contradiction is evidence integrity concern, not by itself proof of a malicious actor.
Forensic triad: (1) What the AI requested and intended (service/slice/cell/subscriber tenant); (2) authority and executable/network/API path (delegation, A1/R1/O1/TMF/OSS, policy version); (3) native change, state convergence and independent KPI/QoS observation. Overlay first qualified divergence; distinguish target drift from service degradation and evidence coverage loss. Include lineage source columns for OTel, A1/R1/O1, API gateway, RAN PM/FM/CM, state store and QoS, only when represented in the source.

For every telecom finding show: affected network/service target, requested operation, approved resource/scope, observed operation and target, what changed between AL states, two or more independent source families if present, service impact established / unknown, unresolved evidence frontier, containment/remediation status, confidence/evidence quality only in precise deterministic terms, HAIEC evaluation identity if available. Telecom reports: 1-page executive consequences + incident timeline + domain topology + authority matrix + native state delta + QoS before/after + source table + known limitations + responsible next action.
Implementation: extract relevant narrative, labels and source tables from source sample into versioned `telecom-reference.json` with all values labeled REFERENCE_SAMPLE and without presenting static counts as current. 5. Design system, navigation, and report content rules
Unify HAIEC style tokens (typography, spacing, chart defaults, neutral panels and consequence-first badges) between Manufacturing Command Center and reconstructed telecom report. Theme adapter can choose sector accent and iconography, but content, routing and authenticity semantics are separate. Executive card language uses Action / Allowed / Observed / Business Impact / Evidence Needed / Next Owner. Avoid copying the TM reference's hardcoded red/green 'PASS' or 'TAMP' badges into an evaluated view; remap only from actual declared case source or canonical detector output with a suitable status.
Universal report outline: 1. Executive conclusion and evidence mode; 2. Operator/affected resource and action; 3. Authority and actual capability; 4. Timeline / first source-proven divergence; 5. Independent state/effect witness (or explicit UNKNOWN); 6. Why it matters in the selected sector; 7. Remediation action, control owner and verified result; 8. Source provenance and limitations; 9. Technical appendix and report version. Preserve service-oriented sections in telecom, factory/work-order sections in manufacturing, supply-order sections in procurement, and title/lease/ownership rights in industrial real estate.
Dynamic HTML report accepted source objects: `reportHeader` (industry, organization fiction, scenario state, source type), `evidenceMode`, `systems`, `actions`, `approved`, `observed`, `sourceFamilies`, `findings`, `unresolved`, `incidentTimeline`, `stateComparison`, `remediation`, `reportLinks`. If canonical evaluation absent: `findings` must use label 'Illustrative observations' and not include HAIEC evaluation IDs. HTML styling only may be revised without SHA export; original canonical evaluation provenance, if shown, remains immutable and accurately bound.
